# herd — подробная инструкция

Для того, кто впервые открывает этот код: что система делает, какая часть кода за что
отвечает, как её обучить и запустить, что уже проверено и что осталось доделать.

Короткий обзор на английском — в `README.md`. Здесь всё подробно и по-русски.

---

## 1. Что это за система

Коровник до 60 коров, 4–5 IP-камер сверху (поля зрения частично перекрываются),
видеопоток идёт в облако. Нужно:

- **узнавать каждую корову без RFID** — сеть сама даёт коровам имена, а если не уверена,
  пишет **NaN**;
- **каждую секунду** записывать позу и занятие каждой коровы: лежит / стоит, ест / пьёт /
  ничего;
- **раз в минуту** снимать 7 секунд видео (burst) и по нему определять **жвачку**,
  уточнять, **кто это** (походка, рисунок), и (когда будут метки) **хромоту**;
- **раз в 3 дня** выдавать CSV по каждой корове; **поднимать тревогу** ветеринару, если
  корова лежит или жуёт заметно иначе, чем обычно; собирать **ответы ветеринара** и
  считать, сколько тревог были ложными;
- каждый **вторник в 10:00** часть коров меняется — система должна это пережить.

Пока своих видео из коровника нет, всё обучается и проверяется на открытом наборе
**CBVD-5** (видео коров сбоку, 10 с на клип, разметка поз и занятий на кадрах раз в
секунду). Чего CBVD-5 дать не может, сделано заготовкой, которая включится на видео из
коровника (раздел 8).

## 2. Карта: требование → где в коде → состояние

| Требование | Где | Состояние |
|---|---|---|
| Найти коров на кадре | детектор RT-DETRv2 (`cowbench/detector.py`, класс `Live`) | работает; на CBVD-5 находит 74% коров (далёких — 51%), см. раздел 6 |
| Камеры перекрываются | маска камеры в конфиге: корова считается там, где центр её рамки (`common.in_mask`) | работает |
| Следить за коровой между кадрами | `pipeline.Tracker` (по перекрытию рамок раз в секунду) | работает |
| Поза и занятие каждую секунду | `model.FrameHeads` на векторе DINOv2 кропа (`pipeline.Camera.second`) | работает; ошибка 2.4–2.6% поза, 17–19% занятие (на рамках разметки) |
| Burst 7 с × 25 к/с раз в минуту, камеры по очереди | `pipeline.Camera.burst`, `step_burst` | работает, проверено на 5 камерах (раздел 6) |
| Маленький Temporal Transformer смотрит на кадры burst | `model.TemporalModel` (3 слоя, d=256) | работает и обучается |
| Отпечаток (embedding) коровы = взвешенное среднее по кадрам | голова `quality` → веса кадров → `fingerprint` | работает; веса учатся (с `--quality 1` — явно) |
| Хороший burst / плохой burst (грязь, закрыта другой коровой) | `--quality 1`: испорченные кадры (`degrade.py`) + голова `burst_quality` | **сделано, нужно обучить на поде** (раздел 5, шаг 6) |
| Походка, узнавание между днями | заготовка `barn_dataset.py` + `train.py --extra-train` | **ждёт видео из коровника** (раздел 8.1) |
| K-means по коровам за неделю, ближайший к отпечатку | `gallery.py`: у каждой коровы до 6 центров k-means по её burst за 7 дней | работает (проверено на синтетике) |
| NaN, если не уверен | `abstain.py`: p(верно) по сходству, отрыву, качеству; порог | работает: на CBVD-5 val отвечает в ~86–91% случаев при ~0.3–1% ошибок |
| Новые коровы по вторникам 10:00 | `gallery.migration_due`, `enroll`, `retire` | работает (синтетика) |
| Жвачка | голова `rumination` на burst + ритм движения (`motion.py`) | работает, но слабо: F1 ≈ 0.39 на CBVD-5 (раздел 8.5) |
| Хромота | голова `lameness` есть, **выключена** | **нет меток** (раздел 8.3) |
| Время: лежит, стоит, ест, пьёт, жуёт, бездельничает | `report.py daily`, `store.py` | работает |
| CSV раз в 3 дня | `herd.py report csv` | работает |
| Тревоги: хромые, отклонения лежания и жвачки | `report.py alerts` (против своей же недели) | работает; какое направление лежания «хуже» — **настройка** (раздел 8.4) |
| Вердикты ветеринара, ложные тревоги | `report.py verdict`, `alert-stats` | работает |
| Хватит ли одного GPU | `herd.py stress` | проверено: 5 камер, GPU занят на 18% (раздел 6) |

## 3. Как это работает в коровнике (поток данных)

```
IP-камеры (RTSP)  →  у каждой камеры кольцевой буфер последних ~10 с (Full HD)
                     у каждой камеры 3 потока: чтение, «раз в секунду», «burst»

раз в секунду (каждая камера):
   кадр → детектор → маска камеры → трекер → кроп каждой коровы 224×224
        → DINOv2-S (заморожен) → FrameHeads → поза, занятие → таблица seconds

раз в минуту (камеры по очереди, сдвиг 60/N с):
   последние 7 с буфера (175 кадров) → детектор на 5 кадрах из 25 → цепочки рамок,
   между ними интерполяция → 175 кропов на корову
        → DINOv2-S → 175 векторов
        → ритм пикселей (motion.py, на CPU параллельно)
        → TemporalModel → вес каждого кадра, отпечаток (512 чисел), качество burst,
                          жвачка, поза, занятие, хромота
        → галерея: ближайшая корова + модель NaN → confirmed / tentative / unknown
        → таблица bursts (кто, жуёт ли, качество …)
        → (если включено) каждый N-й burst — в кэш для обучения

ночью (02:00): галерея пересобирает центры k-means из подтверждённых burst,
               регистрирует новых коров, выводит ушедших
вторник 10:00: начинается смена коров

отчёты: трек → корова (если ≥2/3 подтверждённых burst трека за одну корову, иначе NaN)
        → минуты по коровам и дням → CSV за 3 дня, тревоги, вердикты
```

Почему так:

- **Тяжёлая модель только на маленьких кропах.** Детектор и DINOv2-S лёгкие. Большая
  языковая модель (Muse) пробовалась раньше и даёт около 2 кадров/с — для 5 камер мало.
- **Burst по камере, не по корове:** одни 7 секунд дают всех коров в кадре сразу.
- **GPU делится по батчам,** и работа «раз в секунду» идёт первой. Поэтому большой burst
  не задерживает щелчок «раз в секунду» больше чем на один батч (`pipeline.GpuLock`).
- **Корова считается одной камерой:** маска каждой камеры покрывает только «её» пол.
- **Отчёт не делает вид, что видит всё:** в отчёте есть «наблюдаемые минуты» и доли, а
  не только часы.

## 4. Модели по отдельности

### 4.1 Детектор (`cowbench/detector.py`)

RT-DETRv2 (CNN ResNet-50 + трансформер), дообучен на рамках CBVD-5. Возвращает рамки
коров с уверенностью. Важные настройки:

- **порог** — чем ниже, тем больше далёких коров находит и тем больше лишних рамок;
  `herd.py eval-det` печатает ошибку всей системы при каждом пороге (раздел 6);
- **tiles** — кроме всего кадра детектор смотрит на 2 квадратные половины, далёкая корова
  в 1.8 раза шире; работы примерно втрое больше;
- новый детектор под Full HD: `bash herd/run_pod.sh detector` (вход 1088, увеличенные
  вырезки при обучении, порог по F2 — пропуск коровы дороже лишней рамки).

### 4.2 Энкодер кадра — DINOv2-S (`model.FrameEncoder`)

Заморожен. Из кропа 224×224 даёт вектор: CLS + патчи, усреднённые по сетке GRID×GRID
(при GRID=2 — 384·5 = 1920 чисел). Сетка сохраняет «где что» в кропе (голова / тело).
Обучение («Stage A») идёт на заранее посчитанных векторах — поэтому быстро.

### 4.3 Головы кадра — `FrameHeads`

Поза (стоит/лежит) и занятие (ест/пьёт/ничего) по одному вектору — для пути «раз в
секунду». С `POS=1` получает ещё положение рамки в кадре (кормовой стол — это место в
кадре неподвижной камеры). С `DET_KEYS=1` учится и на рамках детектора, а не только на
рамках разметки.

### 4.4 Temporal Transformer — `TemporalModel`

Вход: 175 векторов кадров burst + реальное время каждого кадра (синусоидальное
кодирование, поэтому пропущенные кадры не ломают ритм). Каждый кадр видит все остальные
кадры burst. Выходы:

| Выход | Что | Как учится |
|---|---|---|
| `quality` (на кадр) | насколько кадр полезен → веса кадров (softmax) | через ID-потерю; с `--quality 1` ещё и напрямую: испорченные кадры (`degrade.py`) должны получать низкую оценку |
| `frame_ids` (на кадр) | отпечаток одного кадра (512) | ID-потеря |
| `fingerprint` | **взвешенное среднее отпечатков кадров** — отпечаток burst | SupCon: два куска одного burst — одна корова, остальные в батче — другие. С данными коровника — все burst одной коровы |
| `burst_quality` | 0–1: найдёт ли этот burst свою корову (хороший/плохой burst) | с `--quality 1`: цель — нашёлся ли отпечаток своей коровы в батче |
| `rumination` | вероятность жвачки | по разметке CBVD-5; с `MOTION=1` получает ещё ритм движения |
| `posture`, `activity` | поза, занятие за burst | по разметке |
| `lameness` | балл хромоты | **нет меток** — выключено |

### 4.5 Ритм движения (`motion.py`)

Жвачка — это жевание примерно раз в секунду. По 175 кропам burst считается спектр
изменения каждого пикселя (кадр в серых тонах, 56×56) за 7 с. В сетке 4×4 берётся
мощность и доля движения в полосах вокруг 1 Гц. На CBVD-5 (вид сбоку, издалека) это
почти не помогло: челюсть занимает пару пикселей.

### 4.6 Галерея (`gallery.py`) — k-means по коровам

У каждой коровы до 6 центров k-means (сферический, по косинусу) по её подтверждённым
отпечаткам за последние 7 дней: лежит, идёт, грязная и чистая выглядят по-разному, одно
среднее их бы смазало. Отпечаток burst сравнивается со всеми центрами всех коров:

- ближайшая корова, сходство, **отрыв от второй**, качество burst → модель NaN → p(верно);
- p ≥ порога → **confirmed** (имя коровы);
- похоже на кого-то, но p ниже → **tentative** (в отчётах — NaN);
- ни на кого не похоже → **unknown** → копится; группа треков, которая часто
  встречается, становится новой коровой `new-<дата>-<n>`.

При первом запуске галерея пустая и так регистрирует всё стадо. Каждую ночь центры
пересчитываются только из подтверждённых burst, поэтому ошибка не закрепляется. Со
вторника 10:00 галерея ждёт новых коров, а не виденных 48 ч после этого выводит.
`names.json` (по желанию) сопоставляет имена с бирками в отчётах.

Отличие от буквы ТЗ: в ТЗ «один k-means на всё стадо». Здесь k-means у каждой коровы
свой, а имена коров появляются через регистрацию — по сути то же «ближайший кластер к
отпечатку», но устойчивее.

### 4.7 Модель NaN (`abstain.py`)

Маленькая логистическая регрессия: p(ответ верный) по сходству, отрыву от второй коровы,
качеству кадров, размеру коровы и (если есть) `burst_quality`. Учится на dev-клипах
(включая испорченные burst, если они сделаны). Порог выбирается так, чтобы среди ответов
ошибок было не больше `MAX_ERROR` (по умолчанию 1%). Решение «не уверен» — это NaN в
отчётах.

## 5. Обучение на поде (CBVD-5)

### 5.1 Всё одной командой

```bash
cd /tools && git pull
RUN=run7 POS=1 bash herd/run_pod.sh     # запускается в tmux "herd"
bash herd/run_pod.sh log                 # смотреть лог
```

Каждый шаг продолжает с места остановки; то, что уже посчитано, не пересчитывается.

| Шаг | Что делает | Где результат |
|---|---|---|
| 1 | Python-окружение `/workspace/herd/.venv` | |
| 2 | CBVD-5 с видео | `/workspace/cbvd5` |
| 3–4 | векторы DINOv2 всех кропов burst и кадров разметки | `/workspace/herd/features/{train,val}/<клип>.npz`, `index.jsonl`, `meta.json` |
| 5 | ритм движения каждого burst (CPU) — `MOTION=1` | `<клип>.motion.npz` |
| 6 | испорченные кадры burst (GPU) — `QUALITY=1` | `<клип>.degraded.npz` |
| 7 | кропы с рамок детектора — `DET_KEYS=1`, нужен детектор | `features/train/keys_aug.*` |
| 8 | обучение и оценка | `/workspace/herd/<RUN>/model.pt`, `eval_val.json`, `heads.json`, `eval-val/` |
| 9 | модель NaN | `<RUN>/abstain.json` |
| 10 | оценка на рамках детектора | `<RUN>/eval_det.json`, `<RUN>/eval-val-det/` |

Переключатели (`ПЕРЕМЕННАЯ=значение bash herd/run_pod.sh`):

| Переключатель | По умолчанию | Смысл |
|---|---|---|
| `RUN` | run1 | имя прогона (папка) |
| `EPOCHS` | 40 | максимум эпох (есть ранняя остановка) |
| `POS` | 0 | 1: головы знают, где корова в кадре (рекомендуется 1) |
| `MOTION` | 1 | ритм движения для жвачки |
| `QUALITY` | 1 | явное обучение «хороший/плохой burst» |
| `DET_KEYS` | 1 | головы кадра учатся и на рамках детектора |
| `GRID` | 2 | сетка патчей DINOv2 (4 — мельче, признаки в 3.4 раза больше) |
| `MARGIN` | 0.1 | поля вокруг рамки в кропе (0.5 оказалось хуже — соседние коровы) |
| `MAX_ERROR` | 0.01 | бюджет ошибок для NaN |
| `DET` | авто | папка `best/` детектора (иначе берётся самый новый обученный) |

## 6. Как читать результаты и что уже получено

### 6.1 Файлы оценки

- `eval_val.json`:
  - `reid_top1_clip`, `reid_top1_all` — узнала ли ту же корову через 3.5 с (среди
    коров клипа / всех);
  - `frame_posture_error`, `frame_activity_error` — ошибки раз в секунду на рамках
    разметки;
  - `rumination_*` — жвачка по burst (`_f1`, `_best_f1`; `_share_true` и
    `_share_called_time` — доля жвачки на самом деле и в отчётах);
  - `frame_quality_auc` — отличает ли голова качества испорченные кадры (1.0 — всегда,
    0.5 — наугад);
  - `reid_spoilt_weighted` и `reid_spoilt_uniform` — узнавание по испорченным burst с
    весами кадров и простым средним; разница — то, что дают веса;
  - `burst_quality_auc` — отличает ли `burst_quality` удачные burst от неудачных;
  - `barn_reid_cross_track_top1` — только с данными коровника: узнавание между треками
    и днями.
- `eval-val/report.md` — подробный отчёт cowbench (по тем же 2532 коровам, что и
  LoRA-прогоны).
- `eval_det.json` и `eval-val-det/` — то же, но рамки даёт детектор, пропущенная корова =
  ошибка; плюс полнота и точность детектора, полнота по размеру коровы, перебор порога.
- `abstain.json` — сколько ответов при каком бюджете ошибок (dev, val, val_spoilt).
- `stress_herd_5cam.md` — хватает ли GPU.

### 6.2 Что получено на CBVD-5 (до `QUALITY`/`DET_KEYS`/нового детектора)

| | значение |
|---|---|
| Ошибка «поза и занятие верны оба», рамки разметки | 19.7% (run4), 21.4% (run5) |
| Поза / занятие | 2.4–2.6% / 17–19% |
| То же на рамках детектора (пропуски = ошибки) | 45.4%; на найденных коровах 26.6% |
| Детектор: полнота / точность (IoU 0.5) | 74.4% / 76.0% (при IoU 0.3: 83.7% / 85.6%) |
| Полнота по размеру коровы: мелкие → крупные | 50.7% → 95.6% |
| Узнавание той же коровы через 3.5 с (все коровы val) | 97.5–98.4% |
| Жвачка F1 | ≈0.39 (ритм движения не помог) |
| NaN: порог под 0.5% ошибок на dev → на val ошибок / отвечает | 0.3% / 86% (run2), 1.0% / 91% (run4) |
| 5 камер, один RTX PRO 6000: успевает / GPU занят / оценка камер | да / 18% / ~22 (кадры 1280, детектор 960 без tiles — с Full HD и tiles перепроверить) |

Высокое узнавание «через 3.5 с» не значит «узнает завтра»: на CBVD-5 нет номеров коров,
каждая корова — в одном 10-секундном клипе. Узнавание между днями проверяется только на
данных коровника.

## 7. Запуск в коровнике

1. `cp herd/config.example.toml barn.toml` и заполнить:
   - `[farm]` — часовой пояс, день и час смены коров;
   - `[[cameras]]` — `id`, `url` (RTSP), `mask` — многоугольник пола, который принадлежит
     только этой камере (координаты 0–1). Каждый участок пола должен быть ровно в одной
     маске;
   - `[model] checkpoint`, `[detector] weights` (и `threshold` из `eval-det`);
   - `[store] path` — где будет SQLite, галерея, кэш.
2. Запуск: `python herd/herd.py run --config barn.toml`. Для записанных файлов вместо
   RTSP: `--start 2026-10-07T06:00` и `url` = путь к файлу.
3. Первые дни галерея регистрирует стадо сама (`new-<дата>-<n>`). Чтобы в отчётах были
   бирки, создайте `names.json` рядом с базой: `{"new-2026-10-07-3": "UA1234"}`.
4. Отчёты:
   ```bash
   python herd/herd.py report --config barn.toml csv                 # последние 3 дня
   python herd/herd.py report --config barn.toml alerts --day 2026-10-07
   python herd/herd.py report --config barn.toml verdict --alert 12 --confirmed yes --diagnosis "..."
   python herd/herd.py report --config barn.toml alert-stats         # сколько тревог подтвердилось
   ```
   Колонки CSV: `period_start, period_end, cow_id, label, observed_min, lying_min,
   standing_min, feeding_min, drinking_min, ruminating_min, idle_min, lying_share,
   rumination_share, lameness_score, lameness_bursts, bursts`. Строка `NaN` — время на
   треках, которым корову назначить не удалось.
5. Для обучения на своих коровах включите `[training_cache] enabled = true` (раздел 8.1).

Нагрузка: до ~20 камер на одном RTX PRO 6000 по GPU (оценка), около 1.5 ГБ RAM на камеру
в Full HD. С `tiles` детектор работает примерно втрое дольше — перепроверьте `stress`.

## 8. Что не завершено и как завершить

### 8.1 Узнавание между днями и походка — нужны видео коровника

**Почему не сделано:** в CBVD-5 нет номеров коров, поэтому модель учит только «та же
корова через несколько секунд». Задачу «через 3.5 с» можно решить по внешности, поэтому
походке модель не учится.

**Что уже готово:** кэш в пайплайне, сборка набора, обучение с идентичностями, оценка
между треками и днями.

**Как завершить:**

1. В `barn.toml`: `[training_cache] enabled = true` (по умолчанию каждый 10-й burst,
   ~250 МБ в час, предел 200 ГБ). Поработать 1–2 недели.
2. `python herd/herd.py barn sheet --cache <store_dir>/training_cache --out tracks.html` —
   страница: по дням, по одной строке на трек, миниатюры коровы и догадка галереи.
3. По странице составить `merges.csv`: строки `identity,track` — треки, которые одна
   корова (identity — её бирка или любое имя). Достаточно нескольких десятков коров за
   несколько дней. Без `merges.csv` трек сам считается коровой (это уже минуты-часы, в
   разных позах).
4. Собрать набор, последние дни — в проверку:
   ```bash
   python herd/herd.py barn build --cache <...>/training_cache --out /workspace/herd/features_barn \
       --merges merges.csv --val-from 2026-11-01
   ```
5. Обучить вместе с CBVD-5 и оценить:
   ```bash
   python herd/herd.py train --features /workspace/herd/features --out /workspace/herd/run_barn1 \
       --pos 1 --motion 1 --quality 1 --extra-train /workspace/herd/features_barn/train
   python herd/herd.py eval --features /workspace/herd/features --out /workspace/herd/run_barn1 \
       --extra-val /workspace/herd/features_barn/val
   python herd/herd.py abstain --features /workspace/herd/features --run /workspace/herd/run_barn1
   ```
   Смотреть `barn_reid_cross_track_top1` в `eval_val.json`: доля burst, для которых
   ближайший burst из другого трека (и дня) — та же корова.
6. Новую модель — в `[model] checkpoint`. Галерею лучше начать заново: удалить папку
   `gallery/` рядом с базой. Старые отпечатки сделаны другой моделью и с новыми не
   сравнимы.

`--gallery-labels 1` дополнительно склеивает треки, которые галерея уверенно назвала одной
коровой. Данных становится больше, но модель учит и ошибки галереи. Включать, только
когда порог NaN строгий.

### 8.2 Детектор для камер сверху

**Почему:** детектор обучен на CBVD-5 (вид сбоку). Сверху коровы выглядят иначе, зато
меньше перекрываются.

**Как завершить:**

1. Нарезать кадры из видео коровника и разметить коров рамками в CVAT. Готовые
   инструменты лежат в `cowbench/label/`: `prelabel.py` (предразметка текущим
   детектором), `cvat2ava.py` (экспорт в формат CBVD-5), инструкция
   `manual_labeling_uk.docx`. Достаточно нескольких сотен кадров с разных камер и в разное
   время суток.
2. Обучить: `python cowbench/detector.py train --root <набор> --out /workspace/herd/detector_top
   --size 1088 --zoom 0.5 --tiles 1 --select f2`.
3. `herd.py eval-det` на размеченных кадрах коровника → порог в конфиг. Затем `stress`.

### 8.3 Хромота — нужны метки

Голова `lameness` есть в модели, но выключена (`[lameness] enabled = false`), потому что
меток хромоты нет ни в CBVD-5, ни у нас.

**Как завершить:**

1. Собрать метки: какая корова и когда хромала. Подойдут оценки ветеринара по шкале
   1–5 — их можно связать с burst через вердикты.
2. Добавить в строки burst поле `lameness` (число) и в `train.py` рядом с `l_post`
   добавить потерю для `o["lameness"]` (регрессия; строки без метки пропускать, как
   `masked_ce`). Сейчас эта голова в обучении не участвует вообще.
3. Включить `[lameness] enabled = true` и задать `alert_score`.

### 8.4 Какое отклонение лежания «хуже»

Неизвестно, тревожить ли, когда корова лежит больше обычного, меньше или в обоих случаях.
Сейчас тревога поднимается в обе стороны: `[alerts] lying_directions = ["low", "high"]`.
После нескольких недель вердиктов посмотрите `report alert-stats` и оставьте то
направление, которое подтверждается.

### 8.5 Жвачка

На CBVD-5 F1 ≈ 0.39 — потолок этого набора. Положительных burst в val мало (~67), вид
сбоку и издалека. Минуты жвачки в отчётах пока завышены (≈25–30% против 15%). Так как
тревоги сравнивают корову с её же неделей, постоянное завышение им вредит меньше.

**Как завершить:** разметить жвачку на видео коровника (отрезки по 7 с: жуёт / не жуёт;
можно в CVAT как занятие) и дообучить. Если сверху челюсть не видно, вместо всей коровы
давать кроп головы и шеи крупнее.

### 8.6 Цвет шкуры и NaN

Однотонных коров (без рисунка) узнавать труднее. Система должна сама чаще говорить по
ним NaN: у них ниже отрыв от второй коровы и ниже `burst_quality`. Проверить это можно
только на коровнике: в `abstain.json` по данным коровника посмотреть, как часто NaN у
таких коров. При необходимости — отдельный бюджет ошибок.

### 8.7 Зоны корма и воды

Занятие «ест/пьёт» сильно зависит от того, где корова. С `POS=1` модель учит это по
положению рамки, но только для камер CBVD-5. Для коровника нужна разметка занятий на
своих кадрах (как в 8.5) или явные зоны кормового стола и поилок в конфиге камеры (не
сделано).

### 8.8 Stage B — дообучение самого энкодера

Сейчас DINOv2 заморожен. Если на данных коровника Stage A упрётся в потолок, следующий
шаг — LoRA на энкодере и обучение от картинок до ответа. Это медленнее (картинки в
цикле), но модель увидит мелкие детали: рисунок шкуры, челюсть.

## 10. Частые проблемы

- **`no trained detector`** — укажите `DET=/путь/к/best` или скопируйте папку
  `detector/best` (в ней `det_train_meta.json`) под `/workspace`.
- **`--quality 1 needs the spoilt frames`** — не сделан шаг 6 (`herd.py degrade`).
- **`--motion 1 needs the motion features`** — не сделан шаг 5.
- **`bursts differ from the extracted ones`** — признаки делались с другой разметкой;
  пересчитайте `extract`.
- **Лог показывает старый прогон** — `bash herd/run_pod.sh log` следит за самым новым
  логом; для конкретного: `RUN=run7 bash herd/run_pod.sh log`.
- **Отчёт cowbench устарел** — после `eval` перезапустите `cowbench.py … score` и
  `report`.
- **Нехватка памяти GPU рядом с другими задачами** — детектор при нехватке переходит на
  CPU (это видно в `stress`), но тогда медленно.

## 11. Словарь

| Термин | Значение |
|---|---|
| burst | 7 с видео 25 к/с, раз в минуту на камеру |
| кроп | вырезанная и приведённая к 224×224 рамка коровы |
| отпечаток (fingerprint) | 512 чисел, описывающих корову по burst; сравниваются косинусом |
| трек | одна и та же корова на одной камере, пока трекер её не потерял |
| галерея | известные коровы и их центры k-means |
| confirmed / tentative / unknown | уверенно эта корова / похоже, но не уверен (NaN) / никто из известных |
| NaN | система честно не знает, кто это |
| re-ID top-1 | доля случаев, когда ближайший отпечаток — та же корова |
| AUC | 1.0 — идеально разделяет, 0.5 — наугад |
| IoU | перекрытие двух рамок (0–1) |
| recall / precision детектора | доля найденных коров / доля рамок, которые действительно коровы |
